# Правила и контекст проекта Neon Sort (colors_filter)

## 1. Структура проекта и платформы
- Репозиторий: GitHub Pages (`panichka48.github.io/colors_filter`).
- Файлы проекта: `_headers`, `index.html`, `style.css`, `game.js`, `progression.js`, `features.js`, `platform.js`, `vk-bridge.js` (локальная копия SDK ВК, не менять на внешний CDN).
- Текущая платформа: VK Mini Apps / VK Игры (`vk-bridge.js`, `platform.js`).
- Следующая цель: адаптация и публикация на **Яндекс Игры** (весь платформенный код — реклама, авторизация, сохранения, лидерборд — изолирован в `platform.js` для лёгкого переключения или автоопределения площадки).
- О модерации ВК пока не напоминать — сейчас идёт полировка механик, UX и фикс багов.

## 2. База данных, синхронизация и античит (Supabase)
- Таблица `leaders` (колонки: `game_id`, `user_id`, `name`, `avatar`, `score`, `rank`, `coins`, `save_data`).
- Полный прогресс игрока (этап, монеты, купленные скины/темы, бустеры, сундуки) автоматически сохраняется и подгружается между устройствами (ПК и телефон) через колонку `save_data` (JSON) при запуске и при каждом значимом действии.
- В Supabase включён SQL-триггер античита `protect_leaders_anticheat()`, который блокирует резкие скачки `score`, `rank`, `coins` при `INSERT` и `UPDATE` (белый список настроен строго по уникальному `user_id` разработчика, без привязки к нику).

## 3. Игровая механика, экономика и баланс
- Главный приоритет геймдизайна: **долгосрочное удержание игрока (Retention)** — не допускать инфляции монет на первых этапах; дешёвые скины покупаются к 3–5 этапу, средние («Энерго-блоки» и др.) — к 12–18 этапу, элитные и кейсы — к 25–50+ этапам.
- Масштаб сложности в `platform.js`: `scaledLvl` с коэффициентом `0.6` (потолок 11 цветов / 13 колб достигается к 100-му этапу).
- Тайные этапы (`?`): строго каждый 5-й этап (`lvl % 5 === 0`).
- Замороженные колбы (`❄️`): включаются с 15-го этапа по 1 колбе, с 30-го этапа по 2 колбы (всплывающее уведомление о льде показывается только при реальном наличии замороженных колб).
- На этапах со льдом или тайными шарами всегда гарантируется минимум 2 пустые колбы во избежание тупиков.
- Всплывающие уведомления про серию побед (`Серия x...`, `СУНДУК СЕРИИ`) отключены в `platform.js`.

## 4. Технические правила правки кода
- **Строгое правило вывода кода:** при отправке длинного кода всегда разбивать его на отдельные блоки размером **не более 150–180 строк** на одно окно, чтобы строки не вылетали за пределы интерфейса чата.
- Всегда поднимать версию кэша скриптов и стилей (`?v=...`) в `index.html` при изменении любого JS или CSS файла.
- При добавлении фич для ПК (например, кнопки полноэкранного режима `#fullscreen-btn`) строго сохранять корректную мобильную вёрстку.
- Перед предложением правок опираться только на прикреплённые актуальные файлы из репозитория, а не угадывать имена классов или структуру разметки.
